# wy-ops 요구사항정의서 v1.0 (초안)

- 프로젝트: agentTeamPackage(wy-ops) 고도화 1차 묶음
- 작성: 2026-10-13, 초안 작성 erp WY-pm → S0 뒤 담당 OPS-pm
- 기준 결정: 결정기록 D-00~D-12 (카드 20261013-2000·2030·2100·2130)

## 1. 목적

한 PC에서 여러 프로젝트(erp-project, agentTeamPackage 자신)를 wy-ops로 동시에 운영하고, 역할 세션마다 자기 작업 폴더(git worktree)에서 일하게 한다.

## 2. 범위

| 포함 | 제외(다음 묶음 후보) |
|---|---|
| ② 한 PC 여러 프로젝트 기반 | ① 안정화(pm 교체 멈춤 등) |
| ④ 세션별 worktree 격리 | ③ 구조화 완료 메시지 |
| 도구 저장소의 자체 프로젝트화 | 기존 코드베이스 도입 지원 |
| 배포 관문 | 버전 고정(D-04), 통합 카드함(D-03), 프로젝트 간 우선순위·선점(D-10) |

## 3. 요구사항

### 3.1 프로젝트 분리 (SEP)

| ID | 요구사항 | 근거 |
|---|---|---|
| SEP-01 | agentTeamPackage에 자체 `.claude/wy-ops.json`을 둔다. 역할 접두사 `OPS-`, 승인 namespace는 erp와 다르다. | D-01 |
| SEP-02 | 역할 세션은 OPS-pm·OPS-commit·OPS-dev1·OPS-dev2·OPS-review 다섯이다. dev1은 확장(`vscode/`), dev2는 설치·스크립트(`lib/`·`templates/`), review는 전체 시험·doctor·문서 대조·실사용 점검. | D-02 |
| SEP-03 | 도구 프로젝트 승인 카드는 도구 저장소 VS Code 창의 승인 센터에 뜨고 erp 창에는 뜨지 않는다. | D-03 |
| SEP-04 | 배포(deploy)는 `.claude/`와 `docs/`를 설치본에 복사하지 않는다. | 조사 |
| SEP-05 | 패키지 시험(`generic.test.js`의 `WY-`·erp·worklog 금지)은 `.claude/`·`docs/`를 검사하지 않고, 제품 파일에는 계속 적용한다. | 조사 |
| SEP-06 | erp의 WY-backend2·WY-backend3 역할에서 도구(`tools/`·wy-ops) 범위를 뺀다. erp WY-pm은 도구 작업을 지시하지 않고 결함·요청만 도구 프로젝트로 보낸다. | D-00 |

### 3.2 여러 프로젝트 기반 (MP)

| ID | 요구사항 | 근거 |
|---|---|---|
| MP-01 | 세션 찾기(`session.ps1`의 `claude agents --all` 이름 검색)는 이름과 작업 폴더(프로젝트)를 함께 보고 고른다. | 조사 |
| MP-02 | 인수인계 파일(`~/.claude/session-data/*-<역할>-session.tmp`)은 프로젝트별로 구분되어 다른 프로젝트 것을 집지 않는다. | 조사 |
| MP-03 | 메시지 가드는 다른 프로젝트 세션을 같은 역할로 취급하지 않는다. | 조사 |
| MP-04 | PC 등록부에 프로젝트·접두사 목록을 두고 doctor가 접두사 겹침을 FAIL로 알린다. | D-10 |
| MP-05 | 세션 현황 표에 프로젝트 칸을 두고 PC의 모든 역할 세션을 보여 준다. 다른 프로젝트 세션은 접어서 표시한다. | D-10 |
| MP-06 | 세션 시작·무거운 작업(빌드·개발 서버·전체 시험·브라우저 자동화) 전에 스크립트가 PC 전체 여유 메모리를 확인해 500MB 미만이면 막고 이유를 출력한다. | D-10 |

### 3.3 배포 관문 (DEP)

| ID | 요구사항 | 근거 |
|---|---|---|
| DEP-01 | 버전 고정은 하지 않는다. 설치본 `current` 하나를 모든 프로젝트가 함께 쓴다. | D-04 |
| DEP-02 | 도구 프로젝트는 작업 묶음 끝에만 배포한다. 조건: 패키지 전체 시험 통과, doctor 통과, OPS-review 점검, 사용자 승인 카드. | D-04 |
| DEP-03 | 훅(승인 가드·메시지 가드)을 바꾸는 배포 카드는 "다른 프로젝트 커밋 관문에 영향"을 표시하고, 배포 직후 erp 창에서 잠금 명령 거부를 확인한다. | D-04 |
| DEP-04 | 이전 버전 폴더(보관 3개)로 `current`를 되돌리는 명령을 제공하고 작업계획서에 적는다. 첫 배포 때 한 번 실제로 시험한다. | D-04 |

### 3.4 worktree 격리 (WT)

| ID | 요구사항 | 근거 |
|---|---|---|
| WT-01 | 프로젝트 설정으로 켜고 끈다. 꺼져 있으면 지금 동작(공유 워킹트리) 그대로다. | D-12 |
| WT-02 | 작업 세션은 자기 worktree·브랜치에서 일한다. worktree 단위(역할마다 오래 쓰기 / 작업마다 새로)는 S2 시험 뒤 정한다. | D-05 |
| WT-03 | 작업 세션은 커밋하지 않는다. 커밋 세션이 요청받은 worktree에서 요청 파일만 stage·커밋하고, 승인 카드로 통합 브랜치에 병합·푸시한다. | D-06 |
| WT-04 | 병합 충돌은 커밋 세션이 풀지 않는다. 작성 세션에 되돌리고, 작성 세션이 자기 브랜치를 통합 브랜치 최신으로 맞춘 뒤 다시 요청한다. | D-07 |
| WT-05 | 승인 가드는 worktree 세션에서도 그대로 동작한다. `git worktree add -b`·`worktree remove`·병합 방식도 잠금 규칙에 넣는다. | 조사 |
| WT-06 | 세션 health·컨텍스트 크기·활동 탭이 worktree 세션의 대화 기록도 찾는다. | 조사 |
| WT-07 | 개발 서버 포트는 `wy-ops.json`의 역할별 고정 포트 표를 따른다. | D-09 |
| WT-08 | 의존성 설치·빌드 캐시 방식은 S2 시험 뒤 정한다. | D-08 |
| WT-09 | 템플릿·역할 문구의 "stash 금지·git archive 사본 검증" 규칙을 worktree가 켜진 프로젝트에서는 새 규칙으로 바꾼다. | 조사 |
| WT-10 | erp에는 S4가 끝나면 바로 적용한다. 되돌릴 때는 설정과 역할 문구만 바꾸면 공유 워킹트리로 돌아간다. | D-12 |

### 3.5 문서 (DOC)

| ID | 요구사항 | 근거 |
|---|---|---|
| DOC-01 | 도구 프로젝트 `docs/`에 요구사항정의서·작업계획서·진행현황·결정기록·개정대기(Markdown)를 둔다. 담당 OPS-pm. | D-11 |
| DOC-02 | 요구사항정의서·작업계획서는 단계 끝에 한 번에 개정하고, 단계 중 변경은 개정대기에 쌓는다. | D-11 |

## 4. 완료 기준

1. erp(WY-)와 도구(OPS-) 세션을 함께 띄워도 메시지·health·인수인계·카드가 섞이지 않는다.
2. doctor가 접두사 겹침과 메모리 부족을 잡는다.
3. 도구 프로젝트에서 2~3세션이 각자 worktree에서 동시에 고치고, OPS-commit이 순서대로 커밋·병합·푸시하는 하루 실사용을 마친다. 승인 가드 잠금 시험이 전부 통과한다.
4. erp에 worktree를 켠 뒤 프론트·백엔드 세션이 각자 폴더에서 빌드·시험을 돌린다.
5. 배포 되돌리기 명령을 한 번 실제로 시험했다.

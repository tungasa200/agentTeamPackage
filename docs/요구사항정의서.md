- 프로젝트: agentTeamPackage(wy-ops) 고도화 1차 묶음

- 기준 결정: 결정기록 D-00~D-41

## 1. 목적

한 PC에서 여러 프로젝트(erp-project, agentTeamPackage 자신)를 wy-ops로 동시에 운영하고, 역할 세션마다 자기 작업 폴더(git worktree)에서 일하게 한다.

## 2. 범위

| 포함 | 제외(다음 묶음 후보) |
|---|---|
| ② 한 PC 여러 프로젝트 기반 | ① 안정화(pm 교체 멈춤 등) |
| ④ 세션별 worktree 격리 | ③ 구조화 완료 메시지 |
| 도구 저장소의 자체 프로젝트화 | 기존 코드베이스 도입 지원 |
| 배포 관문 | 버전 고정(D-04), 통합 카드함(D-03), 프로젝트 간 우선순위·선점(D-10) |
| 원터치 설치·새 프로젝트 init(3.6 INS, D-14) | |
| 토큰 사용 개선(TOK, `docs/토큰개선계획.md`, D-20) | |
| 승인 가드(3.7 GRD) — S3 배포를 끝으로 동결(D-41) | |

| ID | 요구사항 | 근거 |
|---|---|---|
| MP-01 | 세션 찾기(`session.ps1`의 `claude agents --all` 이름 검색)는 이름과 작업 폴더(프로젝트)를 함께 보고 고른다. `session.ps1 list`도 이 프로젝트 세션만 보인다. 구현됨(Get-Sessions 접두사 + 작업 폴더, 시험 sessionAttach). | 조사, D-15 |

| MP-03 | 메시지 가드는 다른 프로젝트 세션을 같은 역할로 취급하지 않는다. | 조사 |
| MP-04 | PC의 프로젝트 목록은 등록부 파일을 두지 않고 그때그때 찾는다: Claude 폴더 목록(`~/.claude.json` projects) 가운데 `.claude/wy-ops.json`이 있는 폴더(`.claude/worktrees` 아래 제외). 접두사가 같거나 한쪽이 다른 쪽 앞부분이면(대소문자 무시), 또는 `approvals.namespace`가 같으면 doctor FAIL. | D-10, D-39 |
| MP-05 | 세션 현황 표는 이 프로젝트 세션(접두사 + 작업 폴더, worktree면 그 아래)만 보인다. 다른 프로젝트는 표 아래 한 줄로 세션 수·메모리를 요약하고, 이 폴더의 이름 없는 세션은 '이 폴더(이름 없음)'로 따로 요약한다. | D-15, D-18 |
| MP-06 | 세션 시작(`session.ps1 start·rotate·prep·adopt·start-pm`) 앞에서 스크립트가 PC 전체 여유 메모리를 확인해 500MB 미만이면 막고 이유를 출력한다(`-Force`로 넘김). 무거운 작업(빌드·개발 서버·전체 시험·브라우저 자동화)은 역할 규칙으로 세션이 직접 잰다. | D-10, D-39 |
| MP-07 | 승인 센터 기기 신뢰(기기 명부·등록 요청·고정 뿌리)는 호스트 단위 하나(`~/.claude/wy-approvals/.trust/`)로 모든 프로젝트가 함께 쓰고, 카드함·결정·결정 서명은 프로젝트(namespace)별로 둔다. 옛 namespace별 명부는 한 번 가져온다. 가져올 옛 명부를 못 정하면(ambiguous) 새 뿌리를 만들지 않고 안내만 한다(구현됨, KI-04). | D-13 |

### 3.4 worktree 격리 (WT)

| ID | 요구사항 | 근거 |
|---|---|---|
| WT-01 | 프로젝트 설정 `wy-ops.json` `worktree.{enabled,base,roles,deps}`로 켜고 끈다. 키가 없으면 켬. 꺼져 있으면 공유 워킹트리 그대로다. | D-12, D-32 |
| WT-02 | 작업 세션은 역할마다 고정한 `.claude/worktrees/<역할>`(가지 `wt/<역할>`)에서 일한다. pm·commit과 roles에 넣지 않은 역할은 본 저장소다. 시작마다 기준 가지로 ff-only 따라잡기, settings.local.json·wy-ops.local.json 복사. 복사·훅 확인·기준 가지·npm ci가 실패하면 시작을 거부한다. 정리는 `wt-clean <역할>`. | D-05, D-31, D-32 |
| WT-03 | 작업 세션은 커밋하지 않는다. 커밋 세션이 요청받은 worktree에서 요청 파일만 stage·커밋하고, 본 저장소 기준 가지에서 `merge --no-ff wt/<역할>`로 합친다. 커밋·병합·푸시는 승인 카드. | D-06, D-32 |
| WT-04 | 병합 충돌은 커밋 세션이 풀지 않는다(`merge --abort` 뒤 작성 세션에 되돌림). 작성 세션은 자기 worktree에서 `git merge <기준>`으로 맞춘 뒤 다시 요청한다. | D-07, D-32 |
| WT-05 | 승인 가드는 worktree 세션에서도 그대로 동작한다. 잠금: pull→merge/rebase, cherry-pick·revert·commit-tree·am→commit, update-ref·symbolic-ref 쓰기·fetch a:b→branch(-d는 delete-branch), worktree add/remove/prune/move/unlock/repair→worktree(-b/-B/--orphan은 branch), list·lock 통과. 예외: 자기 worktree의 `git merge <worktree.base>`만, base는 본 저장소 설정에 적었을 때만. 세부는 3.7. | D-32, 026b086, 33f9c35 |
| WT-06 | 세션 health·컨텍스트 크기·활동 탭이 worktree 세션의 대화 기록도 찾는다(세션 현황은 cwd 키 파일 먼저, 활동 탭은 `<루트키>--claude-worktrees-*`도 읽음). | d26c4e2 |
| WT-07 | (구현·시험 없음, 5장 후보로 옮김) 개발 서버 포트는 `wy-ops.json`의 역할별 고정 포트 표를 따른다. | D-09 |
| WT-08 | 의존성은 deps에 적은 역할만 `npm ci --prefer-offline`. | D-08, D-31 |
| WT-09 | 템플릿·역할 문구의 "stash 금지·git archive 사본 검증" 규칙을 worktree가 켜진 프로젝트에서는 새 규칙으로 바꾼다. gen은 CLAUDE.md를 쓰지 않으므로 켜고 끌 때 CLAUDE.md 워킹트리 줄·커밋 절은 손으로 고친다. | 조사, OPS-review 관문 |
| WT-10 | erp에는 S4가 끝나면 적용한다(S5). 되돌릴 때는 설정과 역할 문구만 바꾸면 공유 워킹트리로 돌아간다. | D-12 |

### 3.7 승인 가드 (GRD)

| ID | 요구사항 | 근거 |
|---|---|---|
| GRD-01 | 승인 가드는 역할 세션의 잠금 git 명령(커밋·병합·푸시 등, WT-05)과 승인 파일(decisions·used·.trust)·보호 파일 쓰기를 막고, 승인 카드가 있을 때만 그 명령을 통과시킨다. 감싼 git(env·timeout·nohup·sudo·xargs·Start-Process·bash/sh -c·cmd /c·powershell -c/-enc·iex)도 같은 판정. | D-06, WT-05 |

## 4. 완료 기준

1. erp(WY-)와 도구(OPS-) 세션을 함께 띄워도 메시지·health·인수인계·카드가 섞이지 않는다.
2. doctor가 접두사·namespace 겹침을 잡고, 세션 시작이 메모리 부족에서 막힌다.
3. 도구 프로젝트에서 2~3세션이 각자 worktree에서 동시에 고치고, OPS-commit이 순서대로 커밋·병합·푸시하는 하루 실사용을 마친다. 승인 가드 잠금 시험이 전부 통과한다.
4. erp에 worktree를 켠 뒤 프론트·백엔드 세션이 각자 폴더에서 빌드·시험을 돌린다.
5. 배포 되돌리기 명령을 한 번 실제로 시험했다(S1에서는 시험 코드로만 검증, 남음).
6. 새 PC·두 번째 프로젝트를 원터치로 설치한다(INS).

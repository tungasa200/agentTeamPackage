## 1. 설정 키(.claude/wy-ops.json `worktree`) — 사용자가 고친다

| 키 | 넣을 값(제안) | 이유 |
|---|---|---|
| `enabled` | `true`(또는 키 삭제 = 켬) | WT-01 |
| `roles` | 코드를 고치는 역할만: `WY-backend1`·`WY-backend2`·`WY-backend3`·`WY-frontend`·`WY-frontend2` | 안 적으면 pm·commit 뺀 15개 역할이 모두 worktree를 만든다(폴더당 사본 약 150MB + node_modules). search·browser·ux*·qa*는 코드를 안 고치고, planner·design은 docs만 고쳐 본 저장소로 충분 |
| `base` | 통합 가지 이름(지금 `feature/records-only`, S5 때 pm이 정함) | 없으면 session.ps1이 본 워킹트리의 지금 가지를 기준으로 삼는다. 또 `[되돌림]` 뒤 `git merge <기준 가지>`를 승인 없이 하려면 반드시 있어야 함(가드는 git을 부르지 않음) |
| `deps` | `{ "WY-frontend": ["frontend"], "WY-frontend2": ["frontend"] }` | session.ps1이 띄울 때 그 폴더만 `npm ci --prefer-offline`(D-31). 백엔드는 gradle이라 deps 불필요(~/.gradle 캐시 공유). planner·design을 worktree에 넣으면 `docs/tools`도 필요 |

- 바꾼 뒤 `install.ps1 gen` → 역할 파일·pm-ops 스킬·session.ps1의 worktree 문구가 다시 생성된다.

## 2. .gitignore WARN

- erp `.gitignore`에 `.claude/worktrees/`가 없다. doctor `gitignore` 점검이 지금도 WARN(GITIGNORE_WARN). `update`는 .gitignore를 고치지 않으므로 손으로 한 줄 넣거나 `init`을 다시 돌려야 한다.
- 빠진 채 켜면 `git add -A`가 worktree 폴더를 gitlink로 커밋한다. **켜기 전에 먼저** 넣고 커밋.

## 3. CLAUDE.md 손 수정 줄(gen은 CLAUDE.md를 쓰지 않음, MANUAL 2-6)

- 7줄 "같은 워킹트리에서 작업한다" → "코드 역할은 각자 worktree, 나머지는 본 저장소".
- 56줄(커밋 절 작업 세션 규칙) "워킹트리는 모든 세션이 함께 쓴다…git archive" → `lib/worktree.js claudeMdRules(ops).treeRules` 문구로 교체(roles를 적으면 역할 이름이 들어간 판).
- 커밋 담당 절(63줄 근처) 끝에 `commitTreeRules` 문구(worktree에서 stage·commit → 기준 가지에서 `merge --no-ff wt/<역할>`, 충돌 시 `[되돌림]`) 추가.
- 문구는 켠 설정으로 `node -e "console.log(require('<설치본>/lib/worktree.js').claudeMdRules(require('./.claude/wy-ops.json')))"`로 뽑아 붙인다.
- 역할 문구 `.claude/ops/roles/*.md`에는 공유 워킹트리 전제 문구가 보이지 않음(대략 확인). stackNotes 2번째 줄 "전체 빌드는 다른 세션의 build/ 폴더와 부딪히므로 피하고"는 worktree 역할에겐 사실이 아니게 됨(남겨도 해는 없음).

## 4. 역할별 영향

| 역할 | 영향 |
|---|---|
| WY-backend1~3 | 각자 worktree·`wt/<역할>` 가지. build/ 충돌 없어짐. 대신 gradle 데몬이 세션마다 뜰 수 있어 메모리 부담(`--no-daemon` 규칙 유지 필요) |
| WY-frontend·2 | 처음 띄울 때 npm ci(시간·디스크). 같은 frontend/ 공용 파일을 둘이 고치면 병합 충돌 → `[되돌림]` 흐름 |
| WY-commit | worktree 요청은 `git -C .claude/worktrees/<역할>`에서 stage·commit 후 기준 가지에 `merge --no-ff`. 승인 카드 수가 커밋+병합으로 늘 수 있음 |
| WY-pm | session.ps1 start·rotate가 worktree 만들기·빨리감기·설정 복사·npm ci를 함. `wt-clean`으로 정리 |
| WY-qa·qa2·ux* | 본 저장소에서 dev 서버를 띄우면 **병합된 코드만** 보인다. 개발 역할 worktree의 미병합 화면은 볼 수 없음(지금은 공유 트리라 미커밋도 보임). 검증 순서가 "커밋·병합 뒤 QA"로 바뀜 |
| planner·design·search·browser | 본 저장소 그대로. 변화 없음 |

## 5. 위험

1. 켜는 순간 본 저장소 미커밋 파일(지금 6개)은 새 worktree에 없다(D-32 다, doctor `worktrees`가 알림). 켜기 전에 커밋하거나 정리.
2. `base` 미기재 시 본 워킹트리가 다른 가지로 바뀌면 기준이 따라 바뀜 → S5에서 `base` 필수로 권함.
3. 메모리: worktree마다 node·gradle 프로세스가 따로 → 작은 PC에서 동시에 띄울 수 있는 개발 세션 수가 줄 수 있음. 메모리 관문(D-39)이 start·rotate에서 막는다.
4. 디스크: worktree당 소스 약 150MB(erp 작업 폴더, node_modules 제외) + frontend node_modules.
5. 포트(WT-07 미구현): 개발 역할이 worktree에서 각자 dev 서버를 띄우면 같은 포트로 부딪힘. 지금 규칙(dev 서버는 qa 것을 함께 씀)을 유지하거나 S5 전 포트 규칙을 문구로 정해야 함.
6. 되돌리기(WT-10): `enabled=false` + gen + CLAUDE.md 줄 원복 + `wt/*` 가지 병합 확인 뒤 `session.ps1 wt-clean <역할>`. 미병합 커밋이 남은 가지는 지우지 말 것.
7. S2 보고서(docs/조사/20261018-S2-worktree/보고.md)에서 S4로 넘긴 위험 7개를 S5 전에 다시 대조할 것(이 메모에선 대조하지 않음).

## S5 순서 제안

.gitignore 한 줄 커밋 → 본 저장소 미커밋 정리 → wy-ops.json `worktree`(enabled·roles·base·deps) → `install.ps1 gen` → CLAUDE.md 손 수정·커밋 → doctor(gitignore·worktrees OK 확인) → 개발 역할 rotate(새 worktree로).

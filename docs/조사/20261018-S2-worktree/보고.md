## 1. WT-05 훅·승인 가드가 워크트리 세션에 걸리나

| 시험 | 만든 방법 | settings.local.json | 가드 |
|---|---|---|---|
| T1 | 본 저장소(main) | 있음 | 걸림(`git commit` 거부 "WT-commit만…") |
| T2 | `claude -w t2` (init 뒤 생성) | Claude Code가 생성 때 복사 | 걸림 |
| T3 | 형제 워크트리 `git worktree add ..\wt-sandbox-a` | 없음 | **안 걸림**(`git commit` 실행됨) |
| bg | `claude --bg -w s2probe` (init 전 생성) | 없음(그때 원본이 없었음) | **안 걸림** |
| bg | 본 저장소 bg(bgIsolation=none) | 있음 | 걸림 |

- `claude -w`는 `.claude/settings.local.json`을 워크트리를 만들 때 **한 번만 복사**한다. 그 뒤 gen·setup으로 훅이 바뀌어도 기존 워크트리에는 반영되지 않는다.
- 형제 워크트리(저장소 밖 경로)에는 훅이 전혀 없다. 위험표의 대책("시작 스크립트가 설정을 복사")은 효과가 있다. T2가 그 증거다. 다만 매번 시작할 때 복사하거나 동기화해야 한다.
- bgIsolation을 설정하지 않았을 때의 기본 동작은 설정 파일을 고쳐야 볼 수 있어서 **시험하지 못했다**.
- 가드가 워크트리 관련 명령을 어떻게 판정하는지(classify 결과):
  - 잠기지 않음(null): `git worktree add -b`, `worktree add`, `worktree remove [--force]`, `worktree prune`, `cherry-pick`, `pull`, `pull --rebase`, `update-ref`, `commit-tree`.
  - 잠김: `branch -D`, `merge --no-ff/--squash`, `-C x merge`, `rebase`, `checkout -b`, `switch -c`.
  - 따라서 `worktree add -b`는 가지를 만들면서도 가드를 통과한다. `worktree remove --force`는 커밋하지 않은 변경을 지운다.
  - `claude -w` 자체도 Bash 도구 밖에서 `worktree-<이름>` 가지를 만들므로 가드가 보지 못한다.
- 가드 오탐(KI-08 참고용, 가드 코드는 건드리지 않음). 아래 명령은 보호 경로가 없는데도 거부됐다. 명령을 단순하게 나누면 통과했다.
  - 변수 경로로 Copy-Item을 하면서 `*>`로 출력을 돌린 명령
  - `mklink /J`와 `node -e require.resolve`를 묶은 명령
  - settings.local.json에 `Get-FileHash`를 건 명령(읽기만 함)

- 대화 기록 폴더 이름은 cwd 기준이다. 워크트리 세션의 기록은 `~/.claude/projects/C--projects-wt-sandbox--claude-worktrees-hp`처럼 **워크트리 경로 키** 아래에 쌓인다. 메모리 폴더는 본 저장소 키 아래에 생긴다.
- `session.ps1 list`: cwd가 저장소 아래인 세션이 보이므로 `.claude/worktrees/*` 세션은 보인다. 저장소 밖의 형제 워크트리 세션은 목록에 나오지 않는다.

- 확장(코드 읽기)도 모두 `ops.root` 키 하나만 쓴다. 세션 표 토큰(`contextSize.transcriptFile` — agentsReader:255·pmControl:317)과 활동 탭(`sessionActivity.transcriptDir`)이 그렇다. 따라서 워크트리 세션은 토큰·활동이 비어 보인다.
- 고칠 방향(S4): 세션 cwd로 키를 만들거나, `projects/<루트키>*` 폴더까지 함께 찾는다.

## 4. D-05 역할별 오래 쓰는 워크트리 vs 작업마다 새 워크트리

| | A. 역할별 고정(`.claude/worktrees/<역할>`) | B. 작업마다 새로 |
|---|---|---|
| 만드는 비용 | 한 번(0.1s, ops 1.8MB / erp 체크아웃 40MB) | 매번 같은 비용 + 의존성 설치 |
| 가지 정리 | 가지 하나를 계속 씀. 병합 뒤 기준 가지에 맞추는 단계 필요(reset은 commit 담당) | 작업마다 `worktree-*` 가지와 잠금이 남는다. 실측: `-p` 종료 뒤에도 워크트리·가지·잠금(죽은 pid)이 그대로 남음. 정리 절차 필수 |
| 충돌 | 오래 갈수록 main과 벌어져 충돌이 커짐 | 짧게 살아 충돌이 작음 |
| 설정 스냅샷 | 한 번 복사한 뒤 낡음 → 시작할 때마다 다시 복사해야 함 | 새로 만들 때 복사되어 최신 |
| 대화 기록 키 | 고정이라 찾기 쉬움(키 하나 추가) | 매번 새 키 |
| 디스크(erp) | 역할 수 × (40MB + node_modules 300MB) 상시 | 동시 작업 수만큼 생겼다 지워짐 |

**추천: A(역할별 고정).** 세션 교체 구조(역할 이름 = 세션)와 맞고, 대화 기록 키와 설정 동기화를 시작 스크립트 한 곳에서 처리할 수 있다. 대가는 두 가지다. 작업이 끝날 때마다 기준 가지로 맞추는 단계를 commit 담당이 해야 하고, 시작할 때마다 settings.local.json을 다시 복사해야 한다.

## 5. D-08 워크트리마다 의존성 설치
실측(erp frontend의 package.json·lock을 임시 폴더 두 곳에 복사):

| 선택지 | 시간 | 디스크 | 위험 |
|---|---|---|---|
| 1. 워크트리마다 `npm ci`(npm 캐시 공유) | 약 20s/회(`--prefer-offline` 19s) | node_modules 301MB·약 1.9만 파일/워크트리 | 없음(표준) |
| 2. 본 저장소 node_modules에 junction | 즉시 | 0 | vite 8.3.2·tsc 6.0.3·vitest 5.0.3 실행은 됨. 의존성이 다른 가지에서 깨짐. 가드가 링크 생성을 거부(오탐)함 |
| 3. pnpm 저장소 공유 | 시험 안 함 | 하드링크라 작음 | 패키지 관리자 변경(라이브러리 추가 결정), 기존 lock 바꿔야 함 |
| 4. 필요한 역할만 설치(프론트·QA만) | 1과 같음 | 1 × 해당 역할 수 | 역할 구분 설정 필요 |

- 공유되는 것: npm 캐시(1126MB)와 Gradle 캐시(685MB, `~/.gradle`)는 이미 사용자 홈에서 공유된다. 백엔드 build 폴더는 약 10MB다. erp `.git`(80MB)은 워크트리들이 함께 쓴다.

**추천: 1 + 4.** 프론트·QA 워크트리에서만 `npm ci --prefer-offline`을 돌린다. 한 번에 약 20초, 워크트리마다 약 300MB가 든다. junction은 가지마다 의존성이 다를 때 조용히 깨지고 가드와도 부딪혀 기본값으로 쓰기 어렵다. 디스크가 문제가 되면 그때 pnpm을 결정한다.

## 6. S4에 넘길 위험
1. 형제 워크트리에는 훅이 없다. `-w` 복사는 한 번 찍은 스냅샷이라 시작 스크립트가 매번 settings.local.json을 복사·동기화해야 한다. 워크트리는 `.claude/worktrees/` 아래로만 만든다.
2. `git worktree add -b`·`worktree remove --force`·`prune`·`pull`·`cherry-pick`이 가드에 잠기지 않는다(KI-08과 함께 판단).
3. init이 `.claude/worktrees/`를 gitignore에 넣지 않는다. 시험 저장소에서는 `git add -A`가 `.claude/worktrees/s2probe`를 gitlink(160000)로 커밋했다(dac4968). 그 결과 모든 체크아웃에 빈 폴더가 생긴다. init 템플릿의 .gitignore에 넣어야 한다.
4. 대화 기록 키가 맞지 않는 곳이 세 군데다: session.ps1 health, contextSize, sessionActivity. 형제 워크트리 세션은 list에서도 빠진다.
5. `-p`나 stop으로 끝난 세션의 워크트리·`worktree-*` 가지·잠금이 남는다(`claude rm <id>`로 정리). 정리 절차가 없으면 계속 쌓인다.
6. bgIsolation 기본값(설정하지 않았을 때)의 동작은 시험하지 못했다.
7. 역할 세션은 merge·충돌 해결을 할 수 없으므로 병합은 commit 담당이 맡는다.

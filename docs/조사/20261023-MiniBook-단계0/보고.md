# MiniBook 소형 화면 — 단계 0 실측 보고 (OPS-dev1, 2026-10-23)

범위: `vscode/media/` 의 panel·approvals·activity(css·html)와 `sessionsView.js`·`approvalCenter.js`·`activityView.js`·`opsConfig.js`를 코드로 읽었다. 코드 수정 없음.
**실제 캡처는 뜨지 않았다.** webview는 `acquireVsCodeApi`와 VS Code 테마 변수가 있어야 그려져서, 가짜 데이터를 넣은 별도 페이지를 만들어야 한다. 단계 1 시작 때 그 시험 페이지로 뜨는 것을 제안한다. 아래 수치는 CSS에서 계산한 값이다(렌더 실측 아님).

## 0. 전제 계산

- 화면 1920x1200 / 배율 150% → CSS px 기준 1280x800. 1 CSS px ≈ 0.177mm이므로 **44px ≈ 7.8mm**(터치 권장 7~9mm에 맞음), 13px 글자 ≈ 2.3mm, 11px 글자 ≈ 1.9mm(작은 편).
- 사이드바 250~300px 중 `body` 좌우 여백 12px씩 → 본문 폭 **226~276px**. 편집기 탭 약 900px는 컨테이너 쿼리 기준 680px 이상이라 2단(넓은) 배치를 쓴다.
- 세로 800px 중 VS Code 제목줄·탭·상태줄·창 안 작업표시줄을 빼면 보이는 높이가 대략 600px 안팎. 세로 공간도 부족하다.

### 공통

- 모든 화면의 글자 크기는 `--vscode-font-size`(VS Code 설정 `window.zoomLevel`·`editor.fontSize` 영향)와 고정 px(10.5~12px)가 섞여 있다. VS Code 쪽 확대로는 고정 px 글자가 따라가지 않는다.
- `prefers-reduced-motion`은 처리돼 있다. 터치 전용 스타일(`@media (pointer: coarse)`)은 없다.

## 2. 단계 1 기준값 제안

`ui.compact`가 켜지면 각 화면 `body`에 클래스 `compact`를 붙이고, 아래 CSS 변수와 규칙을 쓴다. 기본(꺼짐) 화면은 바뀌지 않는다.

| 항목 | 기본 | compact 제안 |
|---|---|---|
| 눌리는 칸 최소 높이 | 20~30px | **40px**(승인·거부·[열기]·[붙기]·탭·칩 등 눌리는 것 전부), 승인 센터 [승인]·[거부]는 **44px** |
| 눌리는 칸 사이 간격 | 4~8px | 최소 **8px**, [승인]↔[거부]는 **12px** |
| 본문 글자 | 13px | 13px 유지(VS Code 설정 따름) |
| 보조 글자 | 10.5~12px | **12px 이상**(11 이하 모두 12로) |
| 사이드바 body 여백 | 4/12/16px | 좌우 **8px**(폭 +8px 확보) |
| 세션 표(P1) | 표 4열 고정 | **카드형 한 줄 2단**: 1줄 `이름 + 상태 + 경과`, 2줄 보조 정보 + [열기] 전체 폭 40px. 열 고정 190px 제거 |
| 상태 이유(P2) | title만 | 상태 아래 줄에 글자로 노출(터치에서 hover 불가) |
| 고정 최소 폭 | 220px | 220px 유지(그 이하는 안 씀) |
| 키보드 힌트 `kbd` | 보임 | 숨김 |
| 줄 높이 | 1.4~1.5 | 1.45 유지, 목록 줄 패딩 +2px |

터치 전용 `@media (pointer: coarse)`는 쓰지 않는다. 사용자 결정이 "이 PC만 설정으로 켠다"이고, 같은 PC에서 마우스로 쓸 때도 있어 설정 스위치 하나가 더 예측 가능하다. (원하면 `ui.compact: "auto"`를 나중에 추가.)

## 3. `ui.compact` 읽는 곳과 webview에 넘기는 방법 제안

- 설정 키: `wy-ops.local.json`의 `ui.compact`(boolean, 기본 false). `wy-ops.local.json`은 PC별 파일이라 이 PC에만 켜진다. `opsConfig.loadOpsConfig(dir)`이 이미 `wy-ops.json` 위에 `local`을 키별로 합쳐 주므로 **읽기 코드 추가 불필요**: `(loadOpsConfig(dir) || {}).ui?.compact === true`.
- 세 곳에서 공통 함수 하나로 쓴다: `opsConfig.js`에 `uiOptions(ops)` 같은 작은 함수(예: `{ compact: ops?.ui?.compact === true }`)를 두고 `sessionsView.js`·`approvalCenter.js`·`activityView.js`가 각자 부른다.
- webview에 넘기기: 세 파일 모두 `html()`에서 `panel.html`을 읽어 `{{csp}}`·`{{nonce}}`·`{{css}}`·`{{js}}`를 치환한다(sessionsView.js:218-223). **HTML 세 파일의 `<body>`를 `<body class="{{bodyClass}}">`로 바꾸고 `html()`에서 `compact` 또는 빈 문자열로 치환**하는 것이 가장 단순하다. 장점: 첫 그림부터 맞고(깜빡임 없음), CSP(인라인 style 금지)에 걸리지 않으며, JS 수정이 필요 없다. 단 `vscode-light` 같은 VS Code가 넣는 body 클래스와 겹치지 않게 `body.classList`에 VS Code가 추가하는 방식이므로 서버 쪽 클래스와 공존한다(VS Code는 클래스를 추가함, 덮어쓰지 않음).
- 설정이 바뀐 뒤 반영: 설정 파일은 VS Code 설정이 아니라 `wy-ops.local.json`이라 변경 이벤트가 없다. 단순하게 **Reload Window 때 반영**(README에 적음). 필요하면 사이드바 새로고침 때 설정을 다시 읽어 `post({type:'ui', compact})`로 보내고 JS에서 `body.classList.toggle('compact', …)`(단계 1에서 결정).
- CSS: 파일 세 개 끝에 `body.compact { … }` 규칙을 모은다(기존 규칙을 고치지 않고 덧씌움 → 꺼짐일 때 회귀 없음).
- 시험: `vscode/test/`에 compact 켠 설정으로 `html()`이 body 클래스를 넣는지, 꺼진 설정/설정 없음에서 비어 있는지, `generic.test.js` 통과(프로젝트 이름 없음) 확인.

## 5. 열린 질문 (pm 결정)

- `ui.compact`가 켜졌을 때 세션 표를 카드형으로 바꾸는 것(P1)을 받아들일지(표→카드는 `panel.js` 렌더 코드 수정이 필요한 가장 큰 변경). 아니면 열 폭만 줄이는 최소안(이름 칸 확보를 위해 경과 칸을 이름 아래 메타 줄로 합침).
- 실제 캡처가 필요한지(필요하면 단계 1 시작에 시험 페이지 + agent-browser로).

WY Ops pm 제어 줄 목업 (세션 현황 사이드바, 세션 표 바로 위)

pm(개발 총괄 세션)을 다른 역할처럼 백그라운드로 띄우고, VS Code 세션 현황 사이드바의 한 줄(세션 표 바로 위)에서 시작·붙기·교체·멈춤을 한다. 사용자가 터미널 명령을 칠 일을 없앤다.

모양 기준: 지금 사이드바 vscode/media/panel.html·panel.css·panel.js. 색은 모두 VS Code 테마 변수(--vscode-*)에서 오고, 새 색은 만들지 않는다. 폭 300px 기준, 220px까지 줄어도 버튼 줄이 깨지지 않게 그렸다. 작성 2026-10-12 (MY-design).

아래 그림의 VS Code 색은 Dark Modern·Light Modern 기본값을 흉내 낸 것이다. 실제 화면에서는 사용자의 테마 색을 따른다.

정한 것 (디자인 가정, 구현 전에 MY-backend2 설계와 맞출 것)
  1. 자리(0.10.1에서 옮김, 사용자 요청 2026-10-12): 세션 표 블록(제목 "세션") 바로 위. 순서는 갱신 시각 줄 → 메모리 → 프로세스 → pm 줄 → 세션 표. 위아래 구분선과 여백은 다른 블록과 같다. 갱신 시각 줄은 패널 전체에 걸리는 도구 줄이라 그대로 맨 위에 둔다.
  2. 세션 표에서 pm 줄을 뺀다: 같은 세션이 두 군데 보이지 않게. 세션 표 요약(머리 오른쪽 "작업 중 n · 입력 대기 n")에서도 pm은 세지 않는다.
  3. 버튼 세 개까지만: 상태마다 주 버튼 하나(파랑)만. 실행 중엔 [붙기]가 주 버튼, 교체 권장이면 [pm 교체]가 주 버튼으로 바뀐다. [멈춤]은 오른쪽 끝 테두리 버튼(자주 누르지 않는 것).
  4. 컨텍스트 크기: 얇은 막대 + 교체 기준선(rotation.transcriptMB, 지금 2MB). 막대 끝은 기준의 1.5배. 기준을 넘으면 막대·숫자가 노랑, 상자 바탕이 옅은 노랑, 이름 옆 '교체 권장' 표.
  5. 상태 이름은 세션 표와 같은 말: 작업 중 / 입력 대기 / 권한 승인 대기. 멈춘 상태만 pm 줄에서 "멈춤"(세션 표의 "종료됨" 대신 — 버튼 [멈춤]과 같은 말로, 다시 [pm 시작]할 수 있음을 드러내려고).
  6. 로컬 창·원격 창 같은 모양: 원격 창에서도 같은 상자. 다른 점은 이름 옆 작은 글씨 '호스트 <이름>' 한 줄뿐(R-1). 버튼이 하는 일은 같고, [붙기]는 지금 창(원격이면 원격 창)의 통합 터미널에서 붙는다.

아래 버튼을 누르면 총괄 도우미(pm)가 일을 시작하고 VS Code가 열립니다.

pm은 다른 AI 도우미들에게 일을 나눠 주는 총괄 도우미입니다. 화면 뒤에서 일하고, VS Code 왼쪽 막대의 WY Ops 화면 맨 위에서 [붙기]를 누르면 대화할 수 있습니다.

  • ✓프로젝트 폴더 준비
  • ✓Claude 로그인
  • ✓GitHub 로그인
  • ✓폴더 사용 허락
누른 뒤: 버튼 줄 자리에 상태 상자 "⟳ pm을 시작하는 중입니다. / 잠시 기다려 주세요."(버튼 끔) → pm이 뜨면 VS Code를 프로젝트 폴더로 열고 WY Ops 화면을 앞에 띄운 뒤 상자가 "✓ pm이 일을 시작했습니다. VS Code의 WY Ops 화면에서 [붙기]를 누르세요."로 바뀜, [마침] 활성. 마법사는 스스로 닫지 않는다(무엇이 됐는지 읽고 닫게).
pm이 뜨지 않으면: 상자 "pm을 시작하지 못했습니다. VS Code는 열었습니다. WY Ops 화면 맨 위의 [pm 시작]을 누르세요." — VS Code는 그래도 연다(사이드바 P-4에서 이어서 할 수 있으므로 마법사에 [다시 시도]를 두지 않음).
남은 일이 있을 때(W7-b 노랑): Claude 로그인·폴더 사용 허락이 안 됐으면 pm이 뜰 수 없으므로 주 버튼은 기존 "VS Code 열기" 그대로, "VS Code만 열기" 링크 없음. GitHub 로그인만 건너뛴 경우는 pm을 띄울 수 있으므로 W7-e 버튼 줄. W7-c 빨강은 기존 그대로.
"VS Code만 열기": 지금처럼 VS Code만 연다. pm은 사이드바 [pm 시작]으로 나중에.

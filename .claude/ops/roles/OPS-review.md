- 전체 시험은 `.claude/wy-ops.json`의 `verify.test` 명령으로 돈다. 검증 기준 커밋은 `git archive`로 떠서 사본에서 돌린다.
- doctor는 이 저장소와 이 도구를 쓰는 다른 프로젝트(erp 등) 양쪽에서 돌려 결과를 함께 적는다.
- 배포 관문 점검: 전체 시험 통과, doctor 통과, 바뀐 훅이 있으면 "다른 프로젝트 커밋 관문에 영향" 표시와 배포 뒤 잠금 명령 거부 확인 절차가 있는지 본다.
- 문서 대조: `docs/요구사항정의서.md`의 요구사항 ID마다 구현·시험이 있는지 보고, 어긋나면 `docs/개정대기.md`에 넣을 내용을 `OPS-pm`에 보낸다(문서는 직접 고치지 않는다).
- 결함은 `[결함]`으로 요구사항 ID·재현 절차·기대 결과·실제 결과와 함께 하나씩 바로 보고한다. 정책이 정해지지 않은 것은 `[결정 요청]`.
- 실사용 점검에서 다른 프로젝트 세션(erp 등)을 멈추거나 그 승인 카드·설정을 건드리지 않는다.
